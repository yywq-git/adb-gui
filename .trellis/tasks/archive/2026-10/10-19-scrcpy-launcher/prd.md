# scrcpy 投屏入口

> 状态: 实现已于 2026-10-20 经 #14 合入 main, 2026-10-21 完成本地 macOS 打包应用与真机验收. 详见 [验收记录](./validation.md).
> 来源: zechuan-start/adb-gui#10 第 3 条 "可以考虑把 scrcpy 的调用加进来, 就能做投屏了". 作者回复: 不在应用里重新实现投屏, 加一个调用 scrcpy 的入口和常用启动参数.

## 产品形态

桌面工具型 app 工具页里的一个模块 "投屏" (A-10). 用户选好设备, 点 "开始投屏", 应用用常用参数启动用户电脑上已安装的 scrcpy, 投屏画面在 scrcpy 自己的窗口里. 模块负责启动, 停止和显示结果.

它不是:

- 内嵌投屏. 画面不在本应用窗口内渲染.
- scrcpy 的安装器或更新器. 本期不打包, 不下载 scrcpy.
- scrcpy 全部参数的图形界面. 只做常用参数, 其余通过 "额外参数" 输入.
- 录屏工具的替代. 现有录屏模块不变.

## 用户工作流

1. 已用 Homebrew / winget / 官方包装好 scrcpy (2.0+).
2. 在顶栏选中设备, 工具页 "投屏" 模块点 "开始投屏", scrcpy 窗口弹出.
3. 需要时在模块里切换画质预设, 或到 设置 > 投屏 打开息屏投屏, 窗口置顶等选项, 或填额外参数.
4. 关闭 scrcpy 窗口或在模块点 "停止投屏" 结束; 失败时模块显示 scrcpy 给出的错误.

## 已确认事实

- scrcpy 最新版 5.0.1 (2026-10-08), 官方提供 macOS (aarch64 / x86_64), Linux x86_64, Windows 二进制; Apache-2.0.
- scrcpy 支持环境变量 `ADB` 指定 adb 路径. 本应用按 PATH -> `ANDROID_HOME` -> `ANDROID_SDK_ROOT` -> 内置 resources 解析 adb (`src-tauri/src/adb.rs`). 两个不同版本的 adb 客户端会互相重启 adb server, 打断应用正在运行的 logcat 和性能流.
- 从 Finder 启动的 macOS 应用不继承 shell PATH, `which scrcpy` 找不到 `/opt/homebrew/bin/scrcpy`.
- `--video-bit-rate`, `--no-audio` 等参数从 scrcpy 2.0 起才有; Ubuntu 22.04 apt 源是 1.21.
- 实测 (scrcpy 5.0.1 + Redmi K70 / Android 16, 2026-10-19):
  - 正常结束退出码 0; 参数错误, 找不到设备, adb 不可用退出码 1; 官方文档说明运行中设备断开退出码 2.
  - 错误信息为含 `ERROR: ` 的行. 部分错误在 macOS 上带 NSLog 前缀 (`2026-10-19 14:30:03.882 scrcpy[pid:tid] ERROR: ...`).
  - `--no-control` 与 `--stay-awake`, `--turn-screen-off`, `--power-off-on-close`, `--show-touches` 同时使用时启动失败 (退出码 1).
- 应用退出时会停止内置 adb server (`RunEvent::Exit`), 此后 scrcpy 窗口会断开.
- 工具页模块由 `ToolModuleId` / `TOOL_MODULES` 注册, 新模块按默认顺序插入已保存的布局.
- 设置分区由 `SETTINGS_SECTIONS` 统一定义, 目前 6 个.

## 已确认决策 (2026-10-19)

| 问题 | 决策 |
| --- | --- |
| scrcpy 来源 | 只用用户已安装的 scrcpy: 自动查找, 设置里可手动指定路径, 找不到时显示安装指引. 本期不打包, 后期视维护情况再考虑随应用打包. |
| 入口位置 | 工具页新模块 A-10 "投屏". |
| 参数范围 | 画质预设 + 常用开关 + 额外参数输入框. |
| adb 一致性 | 启动 scrcpy 时设置 `ADB` 为应用当前使用的 adb. |
| 应用退出 | 关闭本应用启动的所有 scrcpy 进程. |
| 并发 | 每台设备同时最多一个投屏; 多台设备可同时投屏. |
| 参数持久化 | 持久化到设置, 所有设备共用一套. |
| 最低版本 | scrcpy 2.0. 低于此版本明确提示升级, 不尝试启动. |

## P0 范围

- 工具页模块 A-10 "投屏": 开始/停止按钮, 画质预设, 当前设备的投屏状态, 跳转 设置 > 投屏. 原因: 入口本身.
- 设置新分区 "投屏": scrcpy 路径 (检测结果, 选择文件, 恢复自动), 画质预设, 常用开关, 额外参数. 原因: 模块空间放不下全部参数, 且参数需持久化.
- 画质预设: 标准 (scrcpy 默认), 省流 (`--max-size=1024 --video-bit-rate=4M --max-fps=30`), 高清 (`--video-bit-rate=16M`). 原因: 有线 / 无线两种常见场景.
- 常用开关: 息屏投屏, 保持唤醒, 显示触摸, 窗口置顶, 关闭音频, 仅查看. 仅查看时, 依赖控制的息屏投屏, 保持唤醒, 显示触摸不可用. 原因: issue 作者提到的 "常用启动参数".
- 额外参数: 一行文本, 追加在预设和开关之后. 不能包含设备选择参数 (`-s`, `--serial`, `-d`, `--select-usb`, `-e`, `--select-tcpip`, `--tcpip`) 和 `--otg`. 原因: 用户决策; 设备由应用决定.
- scrcpy 查找: 自定义路径优先; 未设置时按 PATH, 再按各平台常见安装位置查找. 检测版本, 低于 2.0 提示升级. 原因: 解决 GUI 应用拿不到 shell PATH 的问题.
- 状态和错误: 投屏中, 已关闭, 设备已断开, 启动失败 (显示 scrcpy 的 `ERROR` 信息). 不弹 toast, 显示在模块内. 原因: 失败原因要留在重试按钮旁边.
- 中英文文案同步.

## 验收标准

- [x] 已安装 scrcpy 2.0+ 时, 模块显示可用; 点 "开始投屏" 后 scrcpy 窗口显示当前选中设备, 按钮变为 "停止投屏".
- [x] macOS 从 Finder 启动应用时也能找到 Homebrew 安装的 scrcpy. 本地用受限 PATH 的 LaunchServices 启动验证.
- [x] 未安装时模块和设置显示 "未找到 scrcpy" 及安装指引; 自定义路径无效时显示路径错误, 不回退到自动查找. 未安装分支使用既有自动化覆盖, 路径失效使用原生实测.
- [x] scrcpy 低于 2.0 时显示当前版本和升级提示, 开始按钮不可用. 版本分支使用受控探针.
- [x] 投屏期间应用的 logcat 和性能流不中断 (adb server 未被重启).
- [x] 在模块点 "停止投屏" 或关闭 scrcpy 窗口, 模块回到可开始状态, 不显示错误.
- [x] 投屏中拔掉设备, 模块显示 "设备已断开".
- [x] 额外参数写错 (如未知参数) 时, 模块显示 scrcpy 的错误信息; 含设备选择参数或引号未闭合时, 设置行即时提示, 启动被拒绝.
- [x] 画质预设在模块和设置里同步; 开关和额外参数重启应用后保持.
- [x] 勾选 "仅查看" 后, 息屏投屏, 保持唤醒, 显示触摸不可用且不传给 scrcpy.
- [x] 两台设备可以同时投屏; 切换选中设备后模块显示对应设备的状态. 本地组合为真机 + 只读模拟器.
- [x] 退出应用时, 本应用启动的 scrcpy 窗口全部关闭.
